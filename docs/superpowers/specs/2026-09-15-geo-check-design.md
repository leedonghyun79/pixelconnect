# GEO 진단 도구 — 설계 기록 (진행 중, 미승인)

> 상태: 브레인스토밍 도중 사용자가 "일단 기록만" 요청 — 아직 최종 승인 안 됨.
> 다음 세션에서 이어서 진행할 때 이 문서부터 읽을 것.

## 배경

참고 사이트: https://twinh.co.kr/geo-check
"URL만 입력하면 구조화 데이터(JSON-LD)와 엔티티 연결성을 100점 만점으로 분석"하는
무료 진단 도구. AI 생성형 검색에서 페이지 인용 준비도를 평가.

twinh 채점 구조:
1. 핵심 엔티티 구성 (55점) — JSON-LD, Organization/WebSite/WebPage/BreadcrumbList 등 필수 요소
2. 속성 완성도 (30점) — 선언된 엔티티의 필수 정보 채움 여부
3. 엔티티 연결성 (15점) — @id 식별자, sameAs 외부연결
페이지 유형(기업/상품/블로그/FAQ/지역/서비스) 자동 감지 후 해당 없는 항목은 N/A 처리.

## 확정된 결정 사항

| 질문 | 결정 |
|---|---|
| 목적 | pixelconnect.co.kr에 **리드제네레이션용 무료 도구**로 추가 (별도 프로젝트 아님) |
| 채점 기준 | twinh와 유사한 100점 루브릭 그대로 (55/30/15 분할) |
| 페이지 유형 감지 | 간단한 규칙기반 감지로 구현 (JSON-LD `@type` 우선, 완벽할 필요 없음) |
| 리드 연결 방식 | 결과는 **무료로 전부 공개**, 하단에 "개선 문의하기" CTA (→ /contact). 이메일 게이트 없음 |
| HTML 파싱 방식 | **cheerio** 라이브러리 도입 (정규식 대신 실제 DOM 파서) |

## 제안했던 아키텍처 (섹션 1 — 아직 사용자 확인 대기 중)

```
사용자 → /geo-check 페이지 (입력폼)
       → POST /api/geo-check (Route Handler)
            → 대상 URL server-side fetch
            → cheerio로 HTML 파싱
              - <script type="application/ld+json"> 전부 추출 → JSON.parse
              - <title>, meta description, og:type, h1 등 보조 시그널 추출
            → 페이지 유형 규칙기반 감지 (JSON-LD @type 우선, 없으면 og:type/URL 패턴 보조)
            → 3개 축 채점 (55/30/15) + 유형별 N/A 처리
       ← JSON 결과 반환
       → 결과 화면 렌더 (점수 게이지 + 항목별 브레이크다운 + "개선 문의하기" CTA)
```

- 서버사이드 fetch라서 CORS 문제 없음. cheerio는 순수 JS라 Cloudflare Workers
  (이 프로젝트는 `nodejs_compat` 플래그 켜져 있음, `wrangler.toml` 참고)에서 문제없이 동작할 것으로 예상 — 실제 빌드/배포 테스트로 확인 필요.
- **SSRF 방지 (필수, 사용자 확인 없이 기본 포함하기로 함)**: 사용자가 입력한 URL이
  `localhost`/사설 IP 대역(`10.x`, `172.16-31.x`, `192.168.x`, `127.x`, `::1` 등)이나
  비-`http(s)` 스킴을 가리키면 서버에서 차단.
- **속도 제한 (필수, 기본 포함하기로 함)**: 동일 IP 기준 분당 N회 제한으로
  무료 프록시/스크래퍼처럼 악용되는 것 방지. 구체적 임계치는 미정.

## 아직 안 정한 것 (다음에 이어갈 때 확인할 질문들)

- [ ] 페이지 경로: `/geo-check`로 확정할지 (twinh와 동일 URL 세그먼트, 사이트 기존 경로들은
      `/services`, `/portfolio`, `/column`, `/contact`, `/reviews`처럼 영단어 한 단어 패턴)
- [ ] 채점 세부 규칙: 55/30/15 안에서 실제로 무엇을 몇 점씩 배분할지 구체적 스펙
      (예: Organization JSON-LD 존재 = 몇 점, `@id` 존재 = 몇 점 등 항목별 배점표)
- [ ] rate limit 임계치, 저장소(Cloudflare KV 등 필요 여부)
- [ ] 결과 화면 UI 목업 (점수 게이지 디자인, 브레이크다운 표시 방식) — 사이트 기존
      네이비/웜옐로 톤 유지가 기본 전제
- [ ] "아키텍처" 섹션 사용자 승인 안 받음 — 다음 섹션(채점 세부 규칙, UI)으로 넘어가기 전
      이 섹션부터 재확인 필요
