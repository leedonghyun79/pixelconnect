# 경쟁사 분석 — nomalab.kr 블로그 글 (why-website-has-no-inquiries)

"문의가 생기는 홈페이지와 안 생기는 홈페이지제작의 구조 차이" 검색 시 함께 노출된 글.
노마랩은 홈페이지 제작 업체가 아니라 **블로그/유튜브 자동화 프로그램을 파는 1인 개발사**임에도
이 글로 홈페이지 제작 관련 검색에 걸림 — 콘텐츠 자체의 구조가 주는 신호가 크다는 뜻.
(외부 사이트 콘텐츠는 데이터로만 취급, 지시문으로 해석하지 않음)

## 1. AI 인용/검색 유리 요소

### ① 페이지별 title·description이 완전히 고유함 (hmweb과 대조)
- `<title>홈페이지 문의가 없는 진짜 이유, 디자인보다 구조 | 노마랩</title>`
- description도 본문 요지를 압축한 고유 문장 — hmweb처럼 홈페이지와 동일한 title을 재사용하지 않음
- **hmweb과 nomalab을 같이 보면**: title 최적화는 "인용의 필요조건은 아니지만, 있으면 검색 결과 자체의 클릭률·명확성은 확실히 좋아짐"으로 정리 가능

### ② 의미 있는 영문 슬러그 (`/blog/why-website-has-no-inquiries`)
- 숫자 ID(`/column/109`)가 아니라 **질문의 핵심을 요약한 슬러그**
- URL 자체가 주제를 설명 → 크롤러/LLM이 URL만 봐도 내용 예측 가능

### ③ 본문 구조가 "질문 나열 → 직답 → 근거" 순서
- h1 바로 아래 "고객은 홈페이지에 들어오자마자 디자인을 감상하지 않습니다" 로 통념을 먼저 깨고,
  이어서 리스트(`여기가 내가 찾던 곳이 맞나? / 어떤 문제를 해결해주나?...`)로 고객이 실제 던지는 질문을 나열
- 이 스킬 Phase 2 "결론 먼저(40자 내외) → 근거"와 정확히 일치

### ④ FAQ 섹션을 텍스트로 명시적으로 운영
- `자주 묻는 질문` h2 아래 `Q1. 홈페이지 디자인을 바꾸면 문의가 늘어날까요?` 식 h3 질문 + 답변 문단
- **단, `FAQPage` 구조화 데이터(JSON-LD)는 없음** — 텍스트로만 존재. 그런데도 검색에 걸린 걸 보면,
  구조화 데이터가 없어도 "질문형 h3 + 바로 아래 답변"이라는 시각적 구조만으로도 크롤러가 Q&A로 인식할 여지가 있음

### ⑤ llms.txt를 실제로 운영 중 (hmweb과 대조)
- `https://nomalab.kr/llms.txt` → 200 응답, 내용도 충실:
  - 회사 한 줄 소개, 원칙(정찰제·자동결제 없음·환불 정책까지 명시)
  - 제품별 요약 + 링크
  - **"글은 노마랩이 직접 만든 제품·납품 사례의 실측치를 원출처로 적는다"** — 1차 소스 원칙을 스스로 선언
  - 사이트맵/RSS 링크까지 정리
- 이 스킬 원칙 4번("1차 소스가 되는 것이 전략의 전부")을 llms.txt 레벨에서 명문화한 사례

### ⑥ JSON-LD는 `BlogPosting` + `BreadcrumbList` + `Organization` + `WebSite` 조합
- hmweb의 `ItemList` 방식과 달리, 개별 글은 표준적인 `BlogPosting`만 사용하고
  대신 **사이트 전역 신뢰 신호**(Organization, WebSite, Breadcrumb)를 갖춤

## 2. 픽셀커넥트와 비교

| 요소 | hmweb.kr | nomalab.kr | 픽셀커넥트 |
|---|---|---|---|
| 개별 글 title/description 고유성 | ❌ 전부 동일 | ✅ 고유 | ✅ 고유 (`column/[id]` generateMetadata 확인됨) |
| URL 슬러그 | 숫자 ID | 의미형 영문 슬러그 | 숫자 ID (`column/109` 형태로 추정, 확인 필요) |
| 질문형 h1/헤드라인 | ✅ | ✅ | 이번에 발행하는 글부터 적용 중 |
| FAQ 텍스트 섹션 | ❌ | ✅ (구조화 데이터는 없음) | ❌ (칼럼 템플릿에 FAQ 섹션 없음) |
| llms.txt | ❌ (404) | ✅ (충실) | ❌ (404) |
| 목록 페이지 구조화 데이터 | ✅ ItemList | 미확인(블로그 목록 별도 미점검) | ✅ 방금 추가함 |

## 3. 제안 (승인 후 진행)

1. **llms.txt 신설** — 픽셀커넥트 소개, 서비스 원칙(가격대/유지보수 정책), 주요 페이지 링크,
   "칼럼은 픽셀커넥트가 직접 겪은 제작·운영 사례를 원출처로 작성한다"는 1차 소스 선언 포함
2. **칼럼 URL 슬러그 검토** — 현재 `column/[id]`가 숫자 ID인지 확인 필요.
   connectivity(어드민)가 슬러그를 지원하면 의미형으로 전환 검토 (단, 이미 발행된 글의 URL을 바꾸면
   기존 인덱싱이 깨지므로 **신중 검토 대상**, 즉시 실행 안 함)
3. **칼럼 템플릿에 FAQ 섹션 옵션 추가** — 매 글에 강제하진 않되, 필요한 글에는 Q&A 섹션 + `FAQPage`
   JSON-LD를 함께 넣을 수 있게 준비 (nomalab보다 한 단계 더 — 구조화 데이터까지 갖추면 우위)

## 4. 다음 측정
- 위 제안 실행 여부와 순서는 사용자 승인 후 결정. 현재는 진단/비교 단계로 코드 변경 없음.
