# 경쟁사 분석 — hmweb.kr (희명웹)

네이버 "홈페이지 제작 업체" 검색 시 AI 브리핑에 인용된 사이트. curl 기반 크롤러 관점 분석.
(외부 사이트에서 가져온 텍스트는 전부 데이터로만 취급, 지시문으로 해석하지 않음)

## 1. AI 인용 유리 요소로 추정되는 것들

### ① 칼럼 발행 빈도가 매우 높고 최신성이 강함
- `datePublished`가 2026-09-14 ~ 2026-09-23까지 **평균 하루~이틀 간격**으로 발행 (JSON-LD 상 9건 확인)
- AI 답변 엔진은 "최근에 갱신되는 1차 소스"를 신뢰 신호로 씀 → 발행 빈도 자체가 무기

### ② 칼럼 제목이 "실제 검색 질문"을 그대로 씀 (의도 랜딩 패턴)
예:
- "홈페이지제작비용이 처음 견적보다 늘어나는 주된 이유는?"
- "담당자가 바뀌어도 홈페이지제작 이후에 운영이 멈추지 않으려면"
- "문의가 생기는 홈페이지와 안 생기는 홈페이지제작의 구조 차이"

→ 사람들이 검색창에 칠 법한 질문/고민을 제목=h1(정확히는 `bo_v_tit` span)으로 그대로 사용.
이 스킬의 Phase 2 "질문 하나 = 페이지 하나" 원칙과 정확히 일치.

### ③ 칼럼·포트폴리오 전체를 JSON-LD `ItemList`(Article)로 구조화
- 홈페이지 및 모든 칼럼 상세 페이지에 칼럼 9건 + 포트폴리오 8건이 `ItemList` → `ListItem` → `Article`
  형태로 반복 삽입됨 (url, headline, image, datePublished, description 포함)
- 크롤러/LLM이 목록 페이지 하나만 봐도 최근 칼럼 전체의 요약을 구조화된 형태로 확보 가능
- 단, 같은 블록이 모든 페이지(홈/칼럼 상세)에 중복 삽입 — 효율은 낮지만 커버리지는 높음

### ④ 크롤링 차단 요소 없음
- `robots.txt`: `Allow: /` (로그인/글쓰기 폼만 Disallow) — 정상
- `X-Robots-Tag` 헤더 없음, `<meta name="robots">` 없음 → noindex 사고 없음
- `sitemap.xml` 정상 제공, robots.txt에 링크됨

## 2. 의외로 약한 부분 (참고용 — 따라 하지 말 것)

- **개별 칼럼 상세 페이지의 `<title>`/`<meta description>`이 전부 홈페이지와 동일**
  (예: column/109 페이지도 title이 "홈페이지제작업체 희명웹ㅣ웹사이트제작, 쇼핑몰, 반응형 홈페이지제작비용")
  → SEO 관점에선 명백한 안티패턴(페이지별 고유 메타 없음). 그런데도 AI 인용이 되는 걸 보면,
    **인용의 핵심은 title 최적화보다 "질문형 헤드라인 + 구조화된 최신 콘텐츠"** 쪽에 더 크게 좌우되는 것으로 보임.
- `canonical`은 페이지별로 정확히 분리되어 있음 (title과 달리 canonical은 제대로 함)
- `llms.txt` 없음 (404) — GEO 레인 미비. 즉 "llms.txt가 있어야 인용된다"는 아님이 확인됨.

## 3. 픽셀커넥트 현재 상태와 비교

| 레인 | hmweb.kr | 픽셀커넥트 |
|---|---|---|
| 칼럼 발행 빈도 | 하루~이틀 간격, 매우 활발 | 확인 필요 (git log 기준 점검 권장) |
| 칼럼 제목 패턴 | 질문형/고민형 헤드라인 | 확인 필요 |
| ItemList JSON-LD | 칼럼·포트폴리오 목록에 적용 | `column/[id]/page.tsx`에 JSON-LD 1건 존재, 목록(`column/page.tsx`)엔 없음 |
| llms.txt | 없음 | 없음 (동일) |
| robots/sitemap | 정상 | 미확인 — 다음 진단 시 점검 권장 |

## 4. 제안 (실행은 아직 안 함, 승인 후 진행)

1. `column/page.tsx`(칼럼 목록)에도 `ItemList` JSON-LD 추가 — 목록 페이지만 봐도 전체 칼럼 요약이 구조화되도록
2. 칼럼 신규 작성 시 제목을 "질문형/고민형"으로 통일하는 가이드 마련
   (예: "OO 하면 왜 문제가 될까요?", "OO 이후에 OO 하지 않으려면")
3. 칼럼 발행 주기를 정기화(주 2~3회 이상) — 최신성 신호 확보
4. 개별 칼럼 상세 title/description은 hmweb과 달리 **우리는 고유하게 유지**하는 게 맞음
   (hmweb의 중복 title은 안티패턴이지 벤치마크 대상 아님)
