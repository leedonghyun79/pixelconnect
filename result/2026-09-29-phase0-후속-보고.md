## ② 크롤러 눈 검증 결과 (curl 증빙)

```
GET /reviews → HTTP 404 (페이지 삭제 확인)

GET /column → 200, 슬러그 링크 확인:
  href="/column/홈페이지-제작-전-기획을-건너뛰면-나중에-무엇이-문제가-될까요"

GET /column/cmtq620x80000q9grpbpzyaub (구 URL) → HTTP 308
  Location: /column/홈페이지-제작-전-기획을-건너뛰면-나중에-무엇이-문제가-될까요
  → 색인된 구 URL 깨짐 없이 리다이렉트 보존됨. 문제없음.

sitemap.xml → 신규 슬러그 URL로 반영됨, /reviews 항목 없음(정상, 페이지 삭제와 일치).
```

## ④ 하지 않은 것과 이유

- **`/reviews`에 Review/AggregateRating 스키마 신설** — 하지 않음. 실제 후기 데이터가 없는 상태에서
  스키마만 넣는 것은 "화면이 거짓말하지 않기" 원칙 위반. 대신 페이지 자체를 없앤 결정이 이미
  반영돼 있어 별도 조치 불필요. 추후 실제 고객 후기가 쌓이면 그때 스키마 포함해 페이지를 재신설하는 것을 권장.
- **네이버 서치어드바이저 사이트맵 제출 상태 점검** — 계정 접근 권한이 없어 코드 레벨 확인 불가.
  사용자가 등록 여부를 알려주면 사이트맵 제출 형식만 마저 점검.
